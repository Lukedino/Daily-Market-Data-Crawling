# 수집·게시 실패의 보존 경계

2026-09-22 후속. 실제 재수집·과거 parquet 정정·가격 정책 변경 없이 코드의 실패 경계를 보완한다.

## 기준본과 게시

- OHLC·KR·재무·sector는 기준본 없음과 읽기 실패를 구분한다. 손상 파일을 빈 DB로 해석하지 않는다.
- Drive 읽기는 폴더를 생성하지 않는다. 전 페이지 목록, 중복 ID/이름, 경로 이탈을 검증한다. 파일 전체를 staging에서 검증한 뒤 교체한다. 유효한 스키마의 0행 parquet 플레이스홀더는 허용하고 0바이트 파일은 손상으로 처리한다.
- 재무와 연도 DB는 원격 기준과 로컬 미게시 이력을 병합한다. 여러 후보를 먼저 검증하고 파일별 원자 교체한다. 이것은 여러 파일 전체의 원자 트랜잭션이나 원격 CAS가 아니다.
- 업로드 응답 미확인·False·예외는 성공이 아니다. 유효한 로컬 수집 결과를 보존해 재게시할 수 있다. 재무는 수집 후 원격 실패 시 다음 flush/배치로 진행하지 않는다.
- sector info 실패 필드는 기존 값과 기존 `updated_at`을 유지한다. 원본 없는 실패 관측은 보류한다. 성공 응답의 필드 부재와 Crypto의 의도된 공란은 실패와 구분한다.

## 원천 날짜와 가격 기준

KR 일별은 고정 FinanceDataReader 0.9.202와 같은 공급 경로에서 원천 날짜를 한 번 선택한 뒤 그 날짜 CSV를 받는다. 세 시장은 같은 응답을 나눈다. 요청한 오늘 날짜를 가격 날짜로 붙이지 않는다. 버전·날짜 증거 불명확 시 보류한다.

KR Yahoo adjusted 후보와 FDR 기존 가격의 기준 일치를 입증하지 못하면 `price_basis_unverified`로 저장을 보류한다. 원래 `auto_adjust=True`를 바꾸거나 과거 값을 자동 재작성하지 않는다. 따라서 기존 fallback/backfill이 후보를 받아도 저장·완료가 차단될 수 있다. 이는 복구 완료가 아니라 가격 정책/출처 확인이 필요한 상태다.

US/Crypto 증분의 실패·빈 결과·요청 종목 누락은 완료 커서를 전진시키지 않는다. 종목별 관측의 보수적 커서를 사용하며 해외 거래소에 US 종료일을 일괄 강제하지 않는다. 직전 저장 세션 overlap·원천 action의 불일치를 감지해 보류한다. 유한 overlap 일치는 전체 과거 조정 기준의 증명이 아니다. 기존 세션·상장/정지 판단 정책은 바꾸지 않는다.

MarketCap은 새 결측 때문에 기존 관측을 지우지 않고, 숫자 0은 결측으로 처리하지 않는다. 현재 시총을 과거 날짜의 봉에 소급 복사하지 않는다. KR OHLC 전용 새 Stocks/Rank는 nullable 값으로 전달하며 기존 유효 메타는 유지한다.

## 실행·로그

`main.py`와 `resave_ohlc.py`, `verify_ohlc.py`, `verify_kr.py`는 같은 `LOCAL_DATA_DIR`의 OS 잠금을 사용한다. 읽기부터 게시까지 잠금을 유지한다. 다른 checkout에서 서로 다른 데이터 디렉터리를 사용하면 별개 잠금이다. GHA 기존 공통 concurrency는 유지하며, 다른 머신/로컬↔GHA까지 직렬화하는 분산 잠금은 아니다. 수동 원격 쓰기는 예약 writer와 겹치지 않는 유지관리 창에서 실행한다.

모든 mode의 dry-run은 수집/기준본 다운로드/데이터 저장/게시 전에 반환한다. CLI 로그 설정 자체는 진단 로그 파일을 만들 수 있지만 운영 데이터와 잠금은 변경하지 않는다.

공개 CLI 로그는 원문 메시지·인수·예외·traceback을 내보내지 않고 소스 파일·줄·고정 이벤트를 기록한다. 주요 보류 원인은 허용된 코드로 표시한다. Python 출력/progress도 공개 수집 실행 중 억제한다. 정상 운영의 상세 payload가 필요한 경우 공개 artifact에 원문을 되살리지 말고 별도 검토한 구조화 필드를 추가한다. native 라이브러리가 OS 파일 디스크립터에 직접 쓰는 출력까지 통제했다고 주장하지 않는다.

수동 resave는 모든 대상 기준본을 먼저 검증하고 실패한 게시를 완료로 보고하지 않는다. pending repair는 원격 pending과 로컬 미게시 intent의 합집합을 단일 게시한다. 후보 종목이나 평일 공백을 실제 역사 누락/휴장으로 확정하지 않는다.

## 운영 반영 시 확인

이 문서는 실제 Drive·시세·DART 수집을 실행한 증거가 아니다. 다음 정상 운영에서 source_date, 보류 코드, 확인된 파일 게시 결과를 대조한다. 장기 이력 재작성, 가격 조정 정책, 임의 staleness 허용일수, 분산 writer 전환은 별도 결정 사항이다.
